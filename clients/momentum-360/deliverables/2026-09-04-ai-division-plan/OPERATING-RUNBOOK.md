## Hourly improvement check

Read the last run state before doing anything. Reuse today's existing Daily Marketing and Web-Build Frontier capture under Dillon OS when available. Review at most three new candidates and fetch at most two primary-source pages. Skip previously evaluated source+revision hashes. Maximum ten minutes per hourly run. Do not launch GPUs, add credit, use a paid research collector or perform an unbounded model loop through this automation.

First choose the concrete bottleneck: repeated extraction, client identity checking, a failed test, slow review, or a documented missing capability. Search installed skills and existing scripts before finding a new package. Read the owning SKILL.md, not the entire skill catalog. New candidates require author/source, license, pinned revision, capability, overlapping tools, dependencies, permission scope, reproducible check, cost and rollback.

A pure documentation skill can be downloaded into a non-active candidate directory, inspected, and promoted to the user skill folder only if it has a clear unmet use case, passes a bounded synthetic test, contains no executable hooks or credential instructions, and introduces no conflicting global rules. Never overwrite an installed skill blindly. Keep an original backup for an explicit upgrade and record the diff. Executable plugins, MCP servers and dependency chains remain evaluated candidates until their specific behavior and installation path have been inspected and tested; do not run code from a social post merely because it calls itself a skill.

Promotion is reversible and in scope when the checks pass. An hourly tick need not install anything. Record accepted/rejected/deferred and why. Keep active skill context small; installation is not proof that a new skill improves work. Regression or no measurable benefit means revert the candidate change.

## Daily business and delivery pass

Once per local day, review the exact Momentum client lane, approved queue items, delivery commitments and recent permitted source deltas. Refresh the vault using its supported scripts first. Use connectors as Codex, then give the model only the relevant redacted source packet. Do not broaden channel membership or pass tokens. Build pending drafts when authorized; do not create a second queue. Reconcile canonical changes only through supported Marketing Chief paths.

Return a short decision packet: current commitments, source freshness, critical blockers, one highest-value improvement, missing business input and evidence-backed next action. Keep source age and uncertainty visible. New client outreach, messages, publication, spend and consequential changes follow their existing explicit authorization, not a model's recommendation.

Before a forecasting experiment, check that the history is sufficient and comparable. Use simple due-date checks and arithmetic scenarios until a held-out backtest demonstrates useful prediction. Report error and uncertainty; never infer a client's actual performance from a generated forecast.

## Prompt contracts

**Extractor:** exact client ID; supplied source locations and observation dates; requested fields and null policy; strict JSON output; no unsupported inference. Validate IDs, counts, date formats and citations with code. Save a source-hash receipt.

**Coder:** one owned directory; concrete behavior; permitted dependencies; acceptance cases including malformed input, retries and boundaries; patch and runnable result. Worker is not alone and must preserve unrelated edits. A reported test pass needs execution evidence.

**Strategist:** decision and options; verified evidence separate from assumptions; economics calculated by code; explicit capacity, adoption and commercial risks; recommendation and disconfirming evidence. No invented market size or customer budget.

**Critic:** fixed draft and evidence; identify the five material defects; classify factual, numerical, operational or authorization error; propose exact changes. Request a concise final rationale, not a transcript of private deliberation.

Every job has a deadline, output cap, one repair allowance and a stop condition. Use small models for bulk extraction/drafts, larger models for selected reasoning, deterministic code for checks, and Codex for the final decision. No indefinite conversation between workers.
