# Radar V2 delivery adapter contract — 2026-09-23

**State:** source audit complete; email and CRM sandbox integration blocked on provider and sandbox account selection. No live send or CRM write was attempted. This contract covers `_os/radar-engine` only.

## Current source contract

- `lib/config.ts` defaults the global kill switch on and report delivery, outreach, email, CRM, and Slack capabilities off. `outboundBlocked()` checks the global and individual flags; it does not inspect an approval record. `.env.example` names no email or CRM provider, sandbox endpoint, sender, or destination.
- `lib/adapters.ts` exposes `email.send(message)`, which always returns `sent:false, dryRun:true`; `crm.handoff(payload)` writes a redacted JSON preview under private `storageDir/crm-previews/` and always returns `written:false, liveWrite:false`. There is no provider transport to invoke. `package.json` has no mail or CRM client dependency.
- `lib/pipeline.ts` creates a campaign with `crm_destination:'dry-run'` and delivery flags false. `packageOutreach()` saves two unsent drafts, inserts an **automatic** `outreach` approval whose reason explicitly says “dry-run drafts only,” calls the CRM preview adapter, records `crm_handoffs` as dry-run, and throws if a live CRM write is reported or CRM is enabled with the kill switch off. This automatic row is not authority for an external action. The email adapter is never called by the pipeline. The fixture's later contacted/booked/won progression is simulated.
- `bin/radar-v2.js serve` registers only `intake.audit`; `lib/jobs.ts` runs supplied handlers and retries errors. `lib/store.ts` deduplicates queued jobs by `idempotency_key`, but deliberately reclaims expired leases only for `intake.audit`. A queued external action cannot be treated as proof of delivery. The existing `crm.send` lease test asserts that an expired running external job is left untouched because an external call might already have happened.
- Reuse the existing fictional `cedar-ridge-hvac` fixture, `createAdapters`, `outboundBlocked`, redaction, approval, job, and private storage patterns. Existing `tests/engine.test.ts` proves dry-run/no outbound and job behavior; `tests/serve-readiness.test.ts` proves persistent storage is required for serving. Do not use the fixture's simulated win as a delivery receipt.
