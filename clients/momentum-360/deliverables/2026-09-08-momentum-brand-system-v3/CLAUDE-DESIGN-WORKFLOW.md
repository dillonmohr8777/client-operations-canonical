# Momentum Claude Design workflow

Verified September 8, 2026. Use current evidence at every major design session.

## Session start
1. Resolve the exact client and existing deliverable. Open the current deployed surface and native Design project. Read current PRODUCT.md, DESIGN.md, source components and asset manifests. Record observed URLs, date, file hashes and unresolved differences. Older memory is a locator, never current proof.
2. Use https://momentum-ai-launch-batch.netlify.app/brand for the current Momentum visual system. Native ebook project: https://claude.ai/design/p/735d088e-aa09-41e7-be15-9afdd92a2948 . Native system project: https://claude.ai/design/p/09b3bbc0-a8f7-4acc-88ae-8a47648d75a4 . Preserve exact logos, Momo, Archivo Black and Nunito Sans. Current user-selected references outrank filename dates.
3. Attach or sync only the relevant Momentum source, actual fonts, imagery and current screenshots. Video files must be under 20 MB in this observed account; preserve originals and use labeled compressed reference copies. Do not grant unrelated client repositories for convenience.
4. Explicitly select the Momentum design system in the native Claude Design project. A Claude Code artifact is not a native Claude Design project.

## Work and finish
Use one clear brief with surface, audience, job, content authority and boundaries. Preserve complete supplied manuscripts. Begin with the core reader and one chapter, then extend the approved pattern across all five. Use targeted changes instead of regenerating the complete project. Check mobile and motion early. Make small direct canvas edits when possible. Finish with chapter and citation counts, actual exercise behavior, exact assets, desktop/mobile and reduced-motion inspection, export, and a verified project link.

After a major design change, update PRODUCT.md or DESIGN.md as appropriate, regenerate the sidecar through Impeccable, and synchronize the native Design system and affected project before reporting both current. Record source hashes and sync status. Never claim automatic synchronization from a registered server alone.

## Claude Code bridge
The documented server was registered at user scope: `claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp`.
Registration is verified; authentication and a completed sync are not verified. Live test in Claude Code 2.1.263: typing `/design-sync` was interpreted as an ordinary model prompt, not a working sync command. The attempt was stopped without claiming sync. The command picker exposed two `/design` entries, including an artifact skill and Design access control. Native Design currently exposes a folder attachment for Link local code. Until the documented command is available and authenticated in this installed account, refresh the bounded source attachment explicitly each major session and record it as a one-time import. Do not claim continuous or automatic sync. The official setup page describes `/design-login` and direct `/design-sync` entry; this installed runtime does not yet verify that documented path. Keep secret values out of prompts and logs. Review exactly which code is shared.

## Reusable prompts

**Start a major session**
> Use current evidence. Open the live Momentum brand page and this native Design project, inspect the latest source files and user-selected references, and list only material mismatches. Attach the Momentum design system. Work on [surface] for [audience] to achieve [job]. Preserve exact logos, fonts, Momo, approved copy and citations. Make one bounded implementation pass and verify desktop, mobile, interaction and reduced motion. Update source and native Design together; report their actual sync state and links.

**Import the five ebooks**
> Create all five complete interactive ebooks IN this native Claude Design project using the supplied source archive. Preserve every manuscript section and citation. Use the Momentum system, exact artwork, readable long-form typography, chapter navigation, restrained motion and the existing practical exercises. Reuse supplied code and content instead of rewriting it. Return a working library and five full readers; verify navigation, saved exercise state, downloads and mobile layouts.

**Refine efficiently**
> Change only [specific component/behavior] to achieve [observable result]. Keep the existing content, assets and system. Show the affected view and verify the requested behavior. Do not regenerate unrelated pages.

**Synchronize a finished session**
> Compare the latest native Design project with the current source and deployed surface. Reconcile approved changes in tokens, components, assets and behavior; update DESIGN.md and its generated metadata. Provide a compact receipt with project link, source revision or hashes, live URL, tests and any remaining differences. Do not describe a one-time import as automatic future sync.
