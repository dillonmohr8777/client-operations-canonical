# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Dependency-light static HTML, CSS, and JavaScript, retained from the exact live deployment. No framework or runtime dependency was introduced. Local answer state uses the existing `putteryPilotDiscoveryV2` storage key and unchanged 69 question IDs.

## Users

Puttery NYC operators and Momentum 360 delivery staff reviewing integration readiness, access dependencies, measurement definitions, and their discovery worksheet.

## Product Purpose

Make the current dated engineering state and next action easy to find, then provide the source-level detail needed to move the pilot forward. The dashboard is a shared review and discovery workspace. It does not ingest or display guest records or current client performance.

## Positioning

The product keeps integration evidence separate from business results. A receiving webhook is a useful milestone. It does not establish booked guest totals, completed visits, collected revenue, or campaign attribution.

## Capabilities and Constraints

- Dated operational status, current next action, source readiness, and expandable evidence.
- Ten integration lanes with scoped evidence, access dependencies, fallbacks, and question jumps.
- Local answer capture, persistence, filters, search, JSON export, and reset that preserves answers.
- Modeled metric examples require explicit disclosure; they are not current performance reporting.
- No live writes, form submissions to vendors, account changes, secret handling, conversion upload, or guest payload retrieval from this public frontend.
- Browser storage failure must explain recovery through export, not claim a successful save.

## Product Principles

1. Lead with the current state and next useful action.
2. Keep source evidence and illustrative performance visibly separate.
3. Preserve the existing worksheet and its export contract.
4. Use progressive disclosure for engineering detail and integration questions.
5. Keep each venue, source, financial definition, and permission explicit.

## Accessibility & Inclusion

Semantic landmarks, heading hierarchy, native details disclosures and form controls, keyboard focus, reduced motion, 44px controls, readable contrast, and no document-level horizontal overflow. The desktop sidebar scrolls within short viewports; mobile navigation remains a horizontal strip.
