The shared build standard

Every page follows one operating system. The structure repeats; the local evidence and writing do not.

Search job

  • City or neighborhood + Halloween bar crawl intent
  • Unique title, description, H1, and supporting headings
  • Natural state naming where ambiguity exists
  • Clear internal links from relevant city and event hubs

Page anatomy

  • Event name, date, time, and location context
  • Concise value statement and event highlights
  • Route area, arrival guidance, and useful FAQs
  • Approved imagery with meaningful alternative text

Source integrity

  • Facts aligned to the current live event record
  • Distinct sections for combined city editions
  • Honest pending state for unconfirmed details
  • No invented venues, inclusions, times, or route claims

Release quality

  • Valid Event schema for each event edition
  • Canonical, indexing, and sitemap checks
  • Mobile layout, links, images, and performance reviewed
  • Final editorial and operational signoff
Definition of done

Published, indexable, internally linked, mobile checked, schema valid, event facts aligned to the current source, and ready for October promotion.
