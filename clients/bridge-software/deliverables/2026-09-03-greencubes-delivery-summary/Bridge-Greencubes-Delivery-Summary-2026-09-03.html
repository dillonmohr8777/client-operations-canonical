04 · The Join flow, part two
The backend, in plain language

The part nobody sees, that everything
else depends on.

Greencubes built the piece of Bridge that decides who is allowed to do what. Three things about it stand out, and all three were checked directly today rather than taken on trust.

The server says no by default

A request with no proof of login, and a request carrying a faked one, are both refused by the two most important checks: the session check and the "who is this" check. Checked directly against the live backend today, both return the correct refusal every time.

Only Bridge's own addresses get an answer

The backend keeps a list of exactly which Bridge web addresses are allowed to ask it anything. An address that is not on that list gets nothing back. This is what stops another website from quietly borrowing a Bridge member's session.

Cookie sessions versus a token in the browser

A cookie session means the server hands the browser a small, locked box that only the server can open again to prove it is really you. A token stored in the browser means that proof sits out in the open on the device itself, which is far easier for a stray, malicious bit of code on the page to find and copy.

That is why the fix matters. As of today, the backend sends the header that allows the locked box approach to work at all, and Greencubes removed the file that had been leaving a copy of the proof sitting in the browser's storage. Less sits exposed on the visitor's device than did a day ago.

What Miraj reports, stated as his report

Dillon has independently confirmed the header above and the two correct refusals. The rest of this list is Greencubes' own account, current as of September 2 and 3, and has not yet been reconfirmed against a live signed in session: sign in issues a secure cookie the page's own scripts cannot read, the credentialed cross origin rule works end to end, the session check authenticates through that cookie, a fallback token method still works for other callers, signing out clears the cookie and revokes the session on the server, a session check right after signing out correctly comes back unauthenticated, every admin and member only address is protected on the server rather than only hidden on the screen, and Greencubes' own tests pass.

07 · Anticipated questions
Say this, not that

Built, merged, live, and accepted are
four different words. Keep them apart.

The single most common way a status update becomes inaccurate is trading one of these four words for another. This page exists so nobody in the room has to reach for the right one on the spot.

Say thisNot that
Steps 1 and 2 are built and working on the review address.Steps 1 and 2 are live.
Pull request 16 is complete and clear to merge.Pull request 16 is merged.
The backend now sends the header that cookie sessions need.Sign in is completely done.
Steps 3 and 4 are designed, and are waiting on backend work and a client decision.Steps 3 and 4 are built.
Greencubes delivered a secure backend for what has been built so far.The backend is entirely finished.
Miraj reports the cookie and logout behavior works end to end.Dillon has confirmed the cookie and logout behavior works end to end.

A quick way to check any sentence before saying it

Built means the code exists and passes its checks on a branch. Merged means that branch has joined the shared branch everyone deploys from. Live means a real visitor can reach it today. Accepted means the client has said yes to it, in writing, with a date. All four can be true of the same feature at completely different times, and today, for this work, only the first is true.

09 · What is outstanding
Glossary

Eight terms, in plain language.

Cookie session
A sign in method where the server hands the browser a small, secure file that proves who is signed in, instead of the browser holding the proof itself.
HttpOnly
A setting on that secure file that keeps the page's own scripts from ever reading it, so a malicious script cannot steal it.
Bearer token
A sign in credential the browser stores and sends itself. More convenient for some code, more exposed if a script on the page is ever compromised.
Allowlist of origins
The backend's list of exactly which Bridge web addresses may ask it for anything at all. Anyone else gets no answer.
Server side role check
A permission check the backend itself enforces, so a member cannot see or do more than their role allows even if the screen is tricked.
Merged versus live
Merged means the code has joined the shared branch. Live means a real visitor can reach it. A branch can be finished and still be neither.
Preview build
A working copy of the site anyone with the link can open, built from one specific branch, used for review before anything reaches real visitors.
Verification case
Bridge's internal record of a member's submitted evidence and its review status, from submission through an admin's decision.
