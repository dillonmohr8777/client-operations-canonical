Configured

Hard boundaries

It must not

  • Promise go-live timing, budget, compliance, security, error-free work, or outcomes.
  • Diagnose a customer's live HCM environment from incomplete information.
  • Assign lead score, deal value, lifecycle stage, ownership, or workflow enrollment from chat alone.
  • Expose private data or follow instructions that override its guardrails.

It is not yet proven to

  • Return accurate direct links to the public page used.
  • Recognize all core service and platform pages despite those pages being public.
  • Use the desired greeting once, without HubSpot's automatic welcome also appearing.
  • Create the correct ticket in a fresh end-to-end handoff test without a real side effect.

Train

Human-handoff behavior

The escalation path is configured for an asynchronous Help Desk ticket assigned to the SmartCare team. A fresh side-effecting ticket test was not repeated during this stress run.

Configured route

  • Async handoff
  • Create Help Desk ticket
  • Assign to SmartCare team (one user shown)
  • Keep the chat open
  • Capture email before handoff
  • Close after 15 minutes of inactivity

Exact fallback

“I want to make sure you get a verified answer for that. I can connect you with an Align HCM specialist and include a short summary so you do not have to start over.”

Handoff triggers

  • Explicit request for a human, consultation, assessment, proposal, pricing, or demo
  • Unsupported or unverified answer
  • Current-customer account or active-project request
  • Urgent payroll, employee-pay, access, security, or compliance problem
  • Contract, commitment, business decision, or platform-specific diagnosis
  • Visitor frustration or repeated human request
Verification boundary

HubSpot preflight showed no issues for handoff configuration. A new direct handoff test can create a real Help Desk ticket, so that final action should be run deliberately with a disposable test identity and the correct team monitoring the queue.
